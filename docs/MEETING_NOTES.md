# Automatic meeting notes (local development)

The app now captures opted-in microphone speech, automatically persists a shared transcript, and refreshes a saved AI recap and suggested next steps. The Notes tab shows the saved recap, draft next steps, design ideas, open questions and source transcript above your written notes. Automatic updates preserve written notes and approved decisions. Export notes downloads Markdown; Add to Actions creates an explicit proposal for review.

## Use it

1. Start the configured local services with `npm run dev:local` and the web preview with `VITE_DEV_AUTH=true npm run dev:web`.
2. The workspace owner enables **Allow transcription when connected** in Settings. This workstation has it enabled following the request to add automatic meeting notes.
3. Open an active room, join the call, and enable your microphone.
4. Check **Automatically transcribe my speech and update meeting notes** in the call panel. Each participant must opt in on their own client. Unconsented remote audio and screen-share audio are not captured.
5. Speech clips save automatically; select **Open saved meeting notes** or the **Notes** tab to view them. The API background worker generates recaps independently of the browser. Suggested actions remain drafts, with no automatic execution or decision approval.

Turning the control off, muting, leaving, ending the room or archiving the project stops new capture. A final clip recorded before stopping may still finish processing. Keep the room open until pending clips save. Failed uploads remain in a bounded in-memory queue with Retry; capture pauses at twelve pending clips. Closing the page loses unsaved audio. The normal unsaved-work navigation guard includes pending clips.

## Local service

`dev:local` optionally starts `scripts/speech-worker.py` alongside the media server. Configure the ignored `.env.local`:

```
SPEECH_ENABLED=true
SPEECH_PYTHON=/path/to/python-with-openai-whisper
SPEECH_MODEL=tiny.en
SPEECH_MODEL_DIR=/private/path/to/model-cache
```

Install Whisper and FFmpeg from official sources. The local worker uses the official [Whisper implementation](https://github.com/openai/whisper) and loads its model once. This workstation has the English `tiny.en` model downloaded to the private work directory; model weights and binaries are excluded from source exports. A fresh machine needs its own installation and model download. The current worker is a local-development service, not a production speech-container deployment.

The worker listens only on `127.0.0.1:8091`, requires a random bearer token generated by the development launcher, rejects oversized clips and concurrent inference, and limits decoded audio to twenty seconds. The authenticated API enforces room access, the owner's workspace transcription setting and explicit per-clip acknowledgement. The server supplies the contributor's verified display name, deduplicates clip IDs, and checks access again after model processing. Audio clips are transient private temporary files, removed after transcription; stored transcripts and recaps remain private business data in the database and encrypted backups. No audio or transcript is sent to a hosted AI service, and neither is logged.

## Validation and limits

The actual speech-to-transcript-to-saved-recap flow passed with the public JFK audio fixture supplied by Whisper. API tests cover authentication, consent, workspace setting, room isolation, duplicate retries, forged contributor fields, recap persistence, unchanged manual notes and access revocation during processing. A database backup was created before migration 005.

Live microphone capture across browsers and multi-person meetings still needs device testing. The initial English model can misrecognize speech; review transcripts and AI suggestions. Short independent recordings can split words at boundaries. One CPU worker processes one clip at a time; larger teams can exceed its capacity. The recap uses bounded recent transcript context plus a previous draft, so long meetings need stronger evidence retrieval and source references. Migration 007 adds a durable recap queue. The API and embedded launcher run a five-second worker tick with database leases, retry backoff and recovery for saved speech. Ended rooms can finish processing; archived projects and disabled transcription settings block processing. A 120-second expired lease is recoverable after a worker crash. This queue handles saved transcripts, not audio still waiting in the browser. Long-meeting coverage and wider AI quality evaluation remain incomplete; suggestions can still be wrong. There is no retained audio replay, transcript correction workflow, retention scheduler or multilingual quality guarantee yet.
